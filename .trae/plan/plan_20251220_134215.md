# SysUserDeptMapper重构计划

## 问题分析

1. **方法重复问题**：

   * `selectUserDeptsByUserNumAndOrgCode` 与 `selectAccessibleDeptsByUserNumAndOrgCode` 方法功能完全相同，都是查询用户在指定机构下的部门信息

   * 缺少直接返回SysUserDept实体对象的查询方法

   * 缺少统一的关联查询方法，获取用户所属所有部门的详细信息

2. **SQL查询问题**：

   * 直接使用`d.*`无法自动转换为驼峰命名，需要明确指定字段并使用别名

## 重构方案

### 1. 移除重复方法

* 删除 `selectUserDeptsByUserNumAndOrgCode` 方法（与 `selectAccessibleDeptsByUserNumAndOrgCode` 重复）

### 2. 新增查询方法

#### 方法1：查询sys\_user\_dept实体列表

```java
/**
 * 通过用户编号查询sys_user_dept表记录列表
 * @param userNum 用户编号
 * @return SysUserDept实体对象集合
 */
@Select("SELECT * FROM sys_user_dept WHERE user_num = #{userNum} AND status = 1 AND is_deleted = 0")
List<SysUserDept> selectUserDeptEntitiesByUserNum(@Param("userNum") String userNum);
```

#### 方法2：查询用户所属部门详细信息（关联sys\_dept表）

```java
/**
 * 通过用户编号查询用户所属部门详细信息（关联sys_dept表）
 * @param userNum 用户编号
 * @return 包含部门详细信息和用户职位的结果集
 */
@Select("SELECT sd.dept_code as deptCode, sd.dept_name as deptName, sd.org_code as orgCode, " +
        "sd.dept_level as deptLevel, sd.sort_order as deptSortOrder, " +
        "sd.dept_description as deptDescription, sd.dept_manager_num as deptManagerNum, " +
        "sud.position as position " +
        "FROM sys_user_dept sud " +
        "LEFT JOIN sys_dept sd ON sud.dept_code = sd.dept_code " +
        "WHERE sud.user_num = #{userNum} AND sud.status = 1 AND sud.is_deleted = 0 AND sd.status = 1 AND sd.is_deleted = 0")
List<Map<String, Object>> selectUserDeptDetailsByUserNum(@Param("userNum") String userNum);
```

### 3. 优化现有方法

* 保留 `selectAccessibleDeptsByUserNumAndOrgCode` 方法，添加更详细的JavaDoc注释

## 预期效果

4. 方法命名规范，注释完整，便于理解和使用
