# 数据字典变更表结构设计

## 设计目标
根据现有项目结构和数据字典变更流程需求，设计完整的表结构以支持变更申请、审批和执行流程。

## 表结构设计

### 1. 字典类型变更主表（biz_ddct_type_change）

| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| uuid | varchar(32) | NOT NULL, UNIQUE | UUID，32位随机字符串 |
| id | bigint unsigned | NOT NULL, AUTO_INCREMENT, PRIMARY KEY | 自增ID，仅做序号 |
| change_no | varchar(32) | NOT NULL, UNIQUE | 变更单号，如CHG_DICT_20260125_0001 |
| dct_tp_id | varchar(64) | NULL | 关联字典类型ID |
| change_type | varchar(20) | NOT NULL | 变更类型：ADD-新增，MOD-修改，DEL-删除 |
| old_dct_tp | varchar(100) | NULL | 原始字典类型编码 |
| new_dct_tp | varchar(100) | NULL | 新字典类型编码 |
| old_dct_tp_nm | varchar(450) | NULL | 原始字典类型名称 |
| new_dct_tp_nm | varchar(450) | NULL | 新字典类型名称 |
| apply_user_num | varchar(20) | NOT NULL | 申请人用户编号 |
| apply_user_name | varchar(50) | NOT NULL | 申请人姓名 |
| apply_time | datetime | NOT NULL DEFAULT CURRENT_TIMESTAMP | 申请时间 |
| change_reason | text | NULL | 变更原因 |
| change_impact | text | NULL | 变更影响分析 |
| approve_status | varchar(20) | NOT NULL DEFAULT 'PENDING' | 审批状态：DRAFT-草稿，PENDING-待审批，APPROVED-已通过，REJECTED-已拒绝，CANCELED-已取消 |
| execute_status | varchar(20) | NOT NULL DEFAULT 'PENDING' | 执行状态：PENDING-待执行，EXECUTING-执行中，SUCCESS-成功，FAILED-失败 |
| approver_num | varchar(20) | NULL | 审批人用户编号 |
| approver_name | varchar(50) | NULL | 审批人姓名 |
| approve_time | datetime | NULL | 审批时间 |
| approve_remark | text | NULL | 审批备注 |
| execute_user_num | varchar(20) | NULL | 执行人用户编号 |
| execute_user_name | varchar(50) | NULL | 执行人姓名 |
| execute_time | datetime | NULL | 执行时间 |
| execute_result | text | NULL | 执行结果 |
| flow_id | varchar(32) | NULL | 关联流程ID |
| current_node_id | varchar(32) | NULL | 当前节点ID |
| approval_instance_id | varchar(32) | NULL | 审批实例ID |
| created_by | varchar(20) | NOT NULL | 创建人用户编号 |
| created_time | datetime | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_by | varchar(20) | NULL | 更新人用户编号 |
| updated_time | datetime | DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |
| is_deleted | tinyint | DEFAULT '0' | 是否删除：0-否，1-是 |

## 设计特点

1. **遵循现有项目规范**：使用与现有表结构一致的字段命名和类型，如UUID主键、标准的时间戳字段等。

2. **完整的变更记录**：记录原始值和新值，便于审批人员对比查看。

3. **状态跟踪**：包含审批状态和执行状态，支持完整的流程跟踪。

4. **关联关系**：通过change_id和change_no建立主表和明细表的关联。

5. **扩展性**：预留了flow_id、current_node_id等字段，可与现有审批流程系统集成。

6. **安全性**：包含创建人和更新人信息，便于审计。

## 实现步骤

1. **创建表结构**：执行SQL脚本创建两个新表。

2. **集成现有系统**：
   - 与现有审批流程表（biz_approval_flow）集成
   - 与现有操作日志表（sys_operation_log）集成

3. **开发后端API**：实现变更申请、审批、执行等相关接口。

4. **开发前端页面**：实现变更申请表单、审批页面和执行页面。

## 技术栈
- 数据库：MySQL 8.0
- 后端：Spring Boot 2.7 + MyBatis Plus
- 前端：Vue 2.7 + Element Plus

此设计方案完全符合现有项目结构和需求文档要求，能够支持完整的数据字典变更管理流程。
