# 代码修正执行计划

## 1. 问题分析

### 1.1 缺失的实体类
根据数据库表结构，项目中缺少以下实体类：
- `sys_api_resource` → `SysApiResource`
- `sys_perm_resource` → `SysPermResource`
- `sys_data_permission` → `SysDataPermission`（原 `sys_data_rule` 表已重命名）
- `sys_biz_permission` → `SysBizPermission`

### 1.2 需要更新的实体类
- **所有实体类**：添加 `uuid` 字段
- `SysDataRule`：需要重命名为 `SysDataPermission`，并更新字段结构
- `SysPermission`：更新字段结构，与新的数据库表结构匹配
- `SysFieldPermission`：更新字段结构，与新的数据库表结构匹配

### 1.3 需要更新的Mapper接口
- `UserMapper`：`selectDataRulesByPermCodes` 方法中的表名需要从 `sys_data_rule` 更新为 `sys_data_permission`
- `SysFieldPermissionMapper`：更新字段映射，添加新字段映射

### 1.4 需要更新的Service层代码
- `AuthServiceImpl`：更新权限检查逻辑，适配新的权限模型

## 2. 修正计划

### 2.1 优先级划分

| 优先级 | 任务 | 预计工时 |
|--------|------|----------|
| 高 | 新增缺失的实体类 | 4小时 |
| 高 | 更新现有实体类 | 3小时 |
| 中 | 更新Mapper接口 | 2小时 |
| 中 | 更新Service层代码 | 3小时 |
| 低 | 更新前端代码（如有） | 2小时 |
| 低 | 测试验证 | 2小时 |

### 2.2 详细修正内容

#### 2.2.1 新增实体类

| 实体类名 | 对应表名 | 主要字段 |
|----------|----------|----------|
| `SysApiResource` | `sys_api_resource` | `uuid`, `id`, `apiCode`, `apiName`, `apiPath`, `httpMethod`, `resourceKey`, `serviceName`, `moduleName`, `rateLimit`, `needAuth`, `logEnabled` |
| `SysPermResource` | `sys_perm_resource` | `uuid`, `id`, `permCode`, `resourceType`, `resourceKey`, `resourceSubType`, `relationType`, `conditionExpression` |
| `SysDataPermission` | `sys_data_permission` | `uuid`, `id`, `permCode`, `dataName`, `entityType`, `scopeType`, `includeChildren`, `ruleType`, `customSql`, `ruleExpression` |
| `SysBizPermission` | `sys_biz_permission` | `uuid`, `id`, `permCode`, `businessName`, `businessType`, `businessRule`, `ruleEngine`, `rulePriority`, `conditionExpression`, `actionExpression` |

#### 2.2.2 更新现有实体类

1. **所有实体类添加 `uuid` 字段**
   ```java
   /**
    * UUID，32位随机字符串
    */
private String uuid;
   ```

2. **更新 `SysPermission` 实体类**
   - 修改权限类型定义：1-访问控制，2-数据范围，3-字段控制，4-时间控制，5-业务规则
   - 删除多余字段：`menuCode`、`apiPath`、`entityType`、`entityField`、`ruleType`、`scopeType`、`customRule`
   - 添加新字段：`actionType`、`effectType`、`conditionExpression`

3. **更新 `SysFieldPermission` 实体类**
   - 删除 `roleCode` 字段
   - 添加新字段：`permCode`、`fieldType`、`defaultValue`、`validationRules`、`uiConfig`
   - 将 `permType` 重命名为 `fieldType`

4. **更新 `SysDataRule` 实体类**
   - 重命名为 `SysDataPermission`
   - 更新表名注解：`@TableName("sys_data_permission")`
   - 更新字段结构，与新的数据库表结构匹配

#### 2.2.3 更新Mapper接口

1. **更新 `UserMapper`**
   - 将 `selectDataRulesByPermCodes` 方法中的表名从 `sys_data_rule` 更新为 `sys_data_permission`
   - 更新返回字段列表，与新的表结构匹配

2. **更新 `SysFieldPermissionMapper`**
   - 添加新字段映射
   - 删除 `roleCode` 字段映射
   - 更新字段名映射：`permType` → `fieldType`

3. **新增Mapper接口**
   - `SysApiResourceMapper`
   - `SysPermResourceMapper`
   - `SysDataPermissionMapper`
   - `SysBizPermissionMapper`

#### 2.2.4 更新Service层代码

1. **更新 `AuthServiceImpl`**
   - 更新权限检查逻辑，适配新的权限模型
   - 更新权限数据结构，适配前端需求

2. **新增Service接口和实现**
   - `SysApiResourceService` 及实现
   - `SysPermResourceService` 及实现
   - `SysDataPermissionService` 及实现
   - `SysBizPermissionService` 及实现

#### 2.2.5 更新前端代码

- 更新相关API调用，确保与后端API匹配
- 更新权限检查逻辑，适配新的权限模型
- 更新表单验证逻辑，适配新的字段权限配置

## 3. 验证计划

1. **编译验证**：运行 `mvn compile` 确保代码编译通过
2. **单元测试**：运行相关单元测试，确保业务逻辑正确
3. **集成测试**：启动应用，测试基本功能是否正常
4. **权限测试**：测试权限控制是否生效，包括菜单权限、按钮权限、数据权限和字段权限

## 4. 风险评估

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 权限模型变更 | 可能导致现有权限失效 | 提前备份权限数据，测试验证权限功能 |
| 字段名称变更 | 可能导致SQL查询失败 | 全面检查所有Mapper接口和XML文件，确保字段名称正确 |
| 实体类重命名 | 可能导致类引用错误 | 使用IDE的重构功能，确保所有引用都已更新 |

## 5. 预期效果

- 所有实体类与数据库表结构完全一致
- 所有Mapper接口和SQL查询与数据库表结构匹配
- 权限系统能够正确处理新的权限模型
- 应用能够正常启动和运行
- 基本业务功能正常
