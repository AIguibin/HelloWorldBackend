# 根据数据库表结构修改实体类

## 1. 问题分析

当前实体类与数据库表结构不一致，导致应用程序在运行时出现SQL语法错误。主要问题包括：

1. **User实体类**：包含数据库中不存在的`role`字段
2. **Menu实体类**：缺少数据库中的`menu_num`字段，且`parent_id`类型不匹配
3. **其他实体类**：可能存在字段不匹配的问题

## 2. 解决方案

### 2.1 设计思路

1. **以数据库表结构为准**：根据实际数据库表结构修改实体类
2. **保持驼峰命名转换**：利用MyBatis-Plus的`map-underscore-to-camel-case`配置，自动将数据库下划线命名转换为实体类驼峰命名
3. **删除不存在的字段**：删除实体类中数据库表不存在的字段
4. **添加缺少的字段**：添加实体类中数据库表存在但实体类缺少的字段
5. **修正字段类型**：修正实体类中与数据库表类型不匹配的字段

### 2.2 实现步骤

1. **修改User实体类**：
   - 删除不存在的`role`字段
   - 确保其他字段与数据库表一致

2. **修改Menu实体类**：
   - 添加缺少的`menuNum`字段
   - 修正`parentId`字段类型为`String`
   - 确保其他字段与数据库表一致

3. **检查其他实体类**：
   - 检查CodeScriptChangeRecord实体类
   - 检查CodeScriptChangeHistory实体类
   - 检查OperationLog实体类
   - 检查Organization实体类
   - 检查Role实体类
   - 检查DictType和DictItem实体类

### 2.3 代码修改

1. **修改User.java**：
   ```java
   // 删除不存在的role字段
   // private String role; // 用户角色：USER/ADMIN（兼容旧字段）
   ```

2. **修改Menu.java**：
   ```java
   // 添加menuNum字段
   private String menuNum; // 菜单编号
   
   // 修改parentId字段类型
   private String parentId; // 父菜单ID
   ```

3. **检查其他实体类**：
   - 根据数据库表结构检查并修改其他实体类

## 3. 预期效果

1. **实体类与数据库表结构一致**：
   - 实体类字段与数据库表字段一一对应
   - 字段类型匹配
   - 不存在多余或缺少的字段

2. **应用程序运行正常**：
   - 不再出现SQL语法错误
   - 可以正常查询和操作数据库

3. **提高代码的可维护性**：
   - 实体类与数据库表结构一致，便于后续开发和维护
   - 符合MyBatis-Plus的最佳实践

## 4. 风险评估

1. **代码兼容性风险**：
   - 删除字段可能影响现有代码
   - 需要检查并修改使用了删除字段的代码

2. **数据类型转换风险**：
   - 修改字段类型可能导致数据转换错误
   - 需要确保应用程序能够正确处理数据类型转换

3. **测试风险**：
   - 修改实体类后需要进行全面测试
   - 确保所有功能正常工作

## 5. 测试计划

1. **单元测试**：
   - 测试实体类的CRUD操作
   - 测试字段类型转换

2. **集成测试**：
   - 测试应用程序启动过程
   - 测试数据库连接和查询

3. **功能测试**：
   - 测试菜单显示效果
   - 测试用户登录功能
   - 测试变更记录管理功能

4. **性能测试**：
   - 测试应用程序启动时间
   - 测试数据库查询性能

通过以上方案，我们可以确保实体类与数据库表结构一致，解决应用程序运行时的SQL语法错误问题。
