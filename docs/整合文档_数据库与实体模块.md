# 数据库与实体模块整合文档

## 1. 概述

数据库与实体模块是平台的基础支撑模块，负责管理数据库表结构、实体类定义、数据初始化和状态字典等核心数据。该模块确保数据库表结构与实体类的一致性，优化数据初始化流程，并管理系统的状态字典，为其他模块提供可靠的数据支持。

## 2. 数据库设计

1. **项目结构修正**：
   - 将项目名称从`aiguibin-online-table`统一改为`aiguibin-platform-arch`
   - 更新构建命令中的输出jar包名称为`aiguibin-platform-arch.jar`

3. **功能描述与实际表结构匹配**：
   - 调整功能描述中的示例，使其与实际表结构完全匹配

## 3. 实体设计

### 3.1 实体类与数据库表结构一致性检查

通过对比数据库表结构和当前实体类，发现了以下差异：

1. **缺失的实体类**：
   - `sys_api_resource` → `SysApiResource`
   - `sys_perm_resource` → `SysPermResource`
   - `sys_data_permission` → `SysDataPermission`（原 `sys_data_rule` 表已重命名）
   - `sys_biz_permission` → `SysBizPermission`

   - 所有实体类：添加 `uuid` 字段
   - `SysDataRule`：重命名为 `SysDataPermission`，并更新字段结构
   - `SysPermission`：更新字段结构，与新的数据库表结构匹配
   - `SysFieldPermission`：更新字段结构，与新的数据库表结构匹配

3. **需要更新的Mapper接口**：
   - `UserMapper`：`selectDataRulesByPermCodes` 方法中的表名需要从 `sys_data_rule` 更新为 `sys_data_permission`
   - `SysFieldPermissionMapper`：更新字段映射，添加新字段映射

## 4. 数据管理

### 4.1 数据初始化流程优化

原数据初始化流程存在硬编码数据的问题，需要进行优化：

1. **问题分析**：
   - 当前 `MenuBootstrap` 类中硬编码了菜单数据
   - 数据初始化逻辑不够灵活，难以维护
   - 缺少统一的数据初始化管理机制

2. **优化方案**：
   - 移除 `MenuBootstrap` 类中的硬编码数据
   - 完全依赖 SQL 脚本进行数据初始化
   - 建立统一的数据初始化管理机制
   - 支持不同环境的数据初始化配置

3. **实施步骤**：
   - 将硬编码的菜单数据转换为 SQL 脚本
   - 更新 `MenuBootstrap` 类，移除硬编码数据
   - 测试数据初始化流程，确保系统能够正常启动
   - 建立数据初始化文档，说明初始化流程和注意事项

### 4.2 数据格式规范

制定了统一的数据格式规范，确保数据的一致性和可读性：

1. **日期时间格式**：
   - 统一使用 ISO 8601 格式：`yyyy-MM-dd HH:mm:ss`
   - 数据库中使用 `datetime` 类型存储
   - Java 中使用 `LocalDateTime` 类型处理

2. **数值格式**：
   - 统一数值精度和小数位数
   - 金额字段使用 `decimal(10,2)` 类型
   - 数量字段使用 `int` 或 `bigint` 类型

3. **字符串格式**：
   - 统一编码格式为 UTF-8
   - 限制字符串长度，避免冗余
   - 关键字段添加索引，提高查询性能

### 4.3 状态字典管理

状态字典用于管理系统中各种状态的定义和映射，确保状态的一致性和可维护性。

1. **当前问题**：
   - 前端组件状态映射仅支持4种状态（01-04），缺少对05-09状态的支持
   - 状态标签显示与字典定义不一致
   - 状态字典更新后，前端组件未及时同步更新
   - 部分前端代码可能存在硬编码的字典数据
   - 缺少完整的字典管理流程和审核机制

2. **状态字典定义**：

| 状态值 | 状态标签 | 说明 |
|--------|----------|------|
| 01 | 草稿态 | 变更记录处于草稿状态，尚未提交 |
| 02 | 已提请 | 变更记录已提交，等待审批 |
| 03 | 审批中 | 变更记录正在审批过程中 |
| 04 | 已合并 | 变更记录已通过审批并合并 |
| 05 | 已部署 | 变更记录已部署到生产环境 |
| 06 | 测试中 | 变更记录正在测试中 |
| 07 | 已评审 | 变更记录已通过技术评审 |
| 08 | 待投产 | 变更记录等待投产 |
| 09 | 已投产 | 变更记录已成功投产 |

3. **状态字典同步更新**：

需要更新以下组件的状态字典映射：

- **ChangeRecord.java**：确保实体类中状态字段的注释与新字典一致
- **ChangeRecordList.vue**：更新 `statusTagType` 函数，支持所有9种状态
- **ChangeRecordHistory.vue**：更新 `statusTagType` 函数，支持所有9种状态
- **ChangeRecordForm.vue**：更新状态选择下拉框，匹配新的字典定义

## 5. 问题修复

### 5.1 修复状态字典处理问题

**问题描述**：前端组件状态映射不完整，仅支持部分状态值，导致状态标签显示错误。

**解决方案**：

1. 更新 `statusTagType` 函数，添加所有状态支持：
   ```javascript
   statusTagType(s) {
     switch (s) {
       case '01': return 'warning'; // 草稿态
       case '02': return 'info';    // 已提请
       case '03': return 'primary'; // 审批中
       case '04': return 'success'; // 已合并
       case '05': return 'success'; // 已部署
       case '06': return 'info';    // 测试中
       case '07': return 'success'; // 已评审
       case '08': return 'warning'; // 待投产
       case '09': return 'success'; // 已投产
       default: return '';
     }
   }
   ```

2. 修正状态值与标签的映射关系，确保显示正确的状态标签

3. 实现字典变更通知机制，及时更新前端缓存

4. 全面检查前端代码，确保所有字典数据动态获取，避免硬编码
