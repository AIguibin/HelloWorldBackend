# 修改MenuBootstrap的initMenuData()方法以遵循RBDA模型规范

## 1. 问题分析

当前的`initMenuData()`方法存在以下问题：
- 硬编码菜单数据，没有基于真实业务数据
- 没有遵循RBDA（Role-Based Data Access）模型规范
- 没有考虑用户机构角色表中的权限数据
- 菜单结构与最新的数据库结构不一致

## 2. 解决方案

### 2.1 设计思路

1. **遵循RBDA模型规范**：
   - 基于角色的数据访问控制
   - 考虑数据权限范围
   - 支持机构层级结构

2. **基于真实业务数据**：
   - 从数据库中读取角色和机构信息
   - 基于角色菜单关系表生成菜单结构
   - 考虑数据权限规则

3. **准确反映数据库结构**：
   - 使用最新的菜单数据结构
   - 支持目录、菜单、按钮、接口四种菜单类型
   - 考虑菜单的可见性和状态

### 2.2 实现步骤

1. **修改菜单初始化逻辑**：
   - 删除硬编码的菜单数据
   - 基于migrate_menu_data.sql中的最新菜单结构
   - 支持RBDA模型的数据权限

2. **添加RBDA模型支持**：
   - 考虑角色的数据权限范围
   - 支持机构层级的数据访问控制
   - 基于用户机构角色表生成菜单

3. **优化菜单生成算法**：
   - 递归生成菜单树结构
   - 支持菜单的排序和状态管理
   - 考虑菜单的可见性设置

### 2.3 代码修改

1. **修改MenuBootstrap类**：
   - 更新initMenuData()方法，使用最新的菜单数据结构
   - 添加RBDA模型支持
   - 基于真实业务数据生成菜单

2. **修改菜单生成逻辑**：
   - 使用递归方式生成菜单树
   - 考虑角色的数据权限
   - 支持机构层级的菜单过滤

3. **添加数据权限支持**：
   - 读取角色的数据权限范围
   - 基于数据权限规则过滤菜单
   - 支持自定义数据权限规则

## 3. 预期效果

1. **菜单结构符合最新数据库设计**：
   - 包含首页、变更管理、版本管理、开发标准、系统设置等主菜单
   - 每个主菜单下有对应的子菜单和按钮权限

2. **遵循RBDA模型规范**：
   - 基于角色的数据访问控制
   - 考虑数据权限范围

3. **基于真实业务数据**：
   - 从数据库中读取角色和机构信息
   - 基于角色菜单关系表生成菜单结构
   - 考虑数据权限规则

## 4. 风险评估

1. **数据库结构变更风险**：
   - 需确保数据库结构与代码逻辑一致
   - 需考虑数据库迁移的兼容性

2. **权限控制风险**：
   - 需确保权限控制逻辑正确
   - 需考虑数据权限的性能影响

3. **系统稳定性风险**：
   - 需确保菜单初始化过程稳定可靠
   - 需考虑异常情况的处理
