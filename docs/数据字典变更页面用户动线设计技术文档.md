# 数据字典变更页面用户动线设计技术文档

## 一、需求概述

### 1.1 功能描述
实现数据字典变更管理系统，用于规范团队对业务数据字典表 `biz_ddct_item`、`biz_ddct_type` 的变更流程，包括变更申请、审批、执行和查询功能，确保变更记录完整可追溯。

### 1.2 功能范围
- ✅ **变更记录列表**：支持分页、多条件组合查询、高级查询
- ✅ **新增变更申请**：创建新的数据字典变更申请
- ✅ **修改变更申请**：修改草稿状态的变更申请
- ✅ **查看变更详情**：查看变更记录的详细信息和对比
- ✅ **变更申请审批**：审批变更申请，支持通过/拒绝
- ✅ **变更执行**：执行已审批通过的变更申请
- ✅ **变更记录查询**：多条件查询变更记录

### 1.3 技术栈
- **后端**：Spring Boot + MyBatis-Plus
- **前端**：Vue 2 + Element UI
- **数据库**：MySQL 8.0+

## 二、用户动线设计

### 2.1 核心用户角色

| 角色 | 职责 | 权限 |
|------|------|------|
| 开发人员 | 提交字典变更申请 | 提交申请、查看历史记录 |
| 审批人员 | 审批变更申请 | 审批操作、查看所有记录 |
| 系统管理员 | 执行变更、系统维护 | 所有权限 |
| 普通用户 | 使用字典数据 | 只读权限 |

### 2.2 主页面用户动线

#### 2.2.1 页面结构设计

**页面路径**：`src/main/webapp/src/views/dict-change/DictChangeRecord.vue`

**页面布局**：

1. **顶部操作区**：
   - 页面标题："数据字典变更记录"
   - 新增按钮："+ 新增变更申请"
   - 高级查询按钮："高级查询"

2. **查询条件区**：
   - 默认显示基本查询条件（变更单号、字典类型、变更类型、审批状态）
   - 点击"高级查询"展开完整查询条件（执行状态、申请人、申请时间范围）
   - 查询按钮和重置按钮

3. **数据列表区**：
   - 表格展示变更记录，包含字段：变更单号、变更类型、原字典类型、新字典类型、申请人、申请时间、审批状态、执行状态、变更原因
   - 操作列：查看详情、修改（仅对草稿状态）

4. **分页区**：
   - 分页控件，支持每页条数调整和页码跳转

#### 2.2.2 用户操作流程

**流程1：新增变更申请**
1. 用户访问变更记录列表页
2. 点击"新增变更申请"按钮
3. 系统跳转至DictChangeApply.vue页面
4. 用户选择变更类型（新增/修改/删除）
5. 系统根据变更类型动态显示表单字段
6. 用户填写变更信息并提交申请或保存草稿
7. 提交成功后返回变更记录列表页，显示新创建的变更记录

**流程2：查看变更详情**
1. 用户访问变更记录列表页
2. 点击列表中某条记录的"查看详情"按钮
3. 系统弹出详情对话框，展示完整的变更信息和对比
4. 查看完成后关闭对话框，返回列表页

**流程3：修改变更申请**
1. 用户访问变更记录列表页
2. 找到状态为"草稿"的变更记录
3. 点击"修改"按钮
4. 系统跳转至DictChangeApply.vue页面，并加载该变更记录的现有数据
5. 用户修改变更信息并提交申请或保存草稿
6. 操作完成后返回变更记录列表页，显示更新后的变更记录

**流程4：高级查询**
1. 用户访问变更记录列表页
2. 点击"高级查询"按钮
3. 展开完整查询条件表单
4. 填写查询条件并点击"查询"按钮
5. 列表页显示符合条件的变更记录
6. 点击"重置"按钮清空所有查询条件

### 2.3 变更申请页面动线

#### 2.3.1 页面结构设计

**页面路径**：`src/main/webapp/src/views/dict-change/DictChangeApply.vue`

**页面布局**：

1. **变更类型选择区**：
   - 单选按钮组：新增、修改、删除
   - 切换变更类型时，动态调整表单字段

2. **字典类型选择区（修改/删除时）**：
   - 下拉选择框：加载所有启用的字典类型
   - 选择后自动加载该字典类型的所有信息和字典项

3. **字典类型信息区**：
   - 新增/修改时显示：字典类型编码、名称、描述
   - 修改时自动填充原始值，可修改新值

4. **字典项变更区**：
   - 添加字典项按钮
   - 字典项列表，支持新增、修改、删除操作
   - 每个字典项包含：操作类型、排序号、字典键、字典值名称、字典值、字典组、字典描述

5. **变更原因与影响区**：
   - 变更原因：必填，多行文本输入
   - 变更影响：可选，多行文本输入

6. **操作按钮区**：
   - 提交申请按钮
   - 保存草稿按钮
   - 重置按钮

#### 2.3.2 用户操作流程

**流程1：新增字典类型**
1. 选择变更类型为"新增"
2. 填写字典类型信息（编码、名称、描述）
3. 点击"添加字典项"按钮，填写字典项信息
4. 重复步骤3添加多个字典项
5. 填写变更原因和变更影响
6. 点击"提交申请"或"保存草稿"

**流程2：修改字典类型**
1. 选择变更类型为"修改"
2. 从下拉列表中选择要修改的字典类型
3. 系统自动加载该字典类型的所有信息和字典项
4. 修改字典类型信息和字典项
5. 可以新增或删除字典项
6. 填写变更原因和变更影响
7. 点击"提交申请"或"保存草稿"

**流程3：删除字典类型**
1. 选择变更类型为"删除"
2. 从下拉列表中选择要删除的字典类型
3. 系统自动加载该字典类型的信息，供用户确认
4. 填写变更原因和变更影响
5. 点击"提交申请"或"保存草稿"

2. **添加数据加载逻辑**：
   ```javascript
   mounted() {
     // 加载字典类型列表
     this.loadDictTypes();
     
     // 检查URL参数，如存在变更ID则加载数据
     const changeId = this.$route.query.changeId;
     if (changeId) {
       this.loadChangeDetail(changeId);
     }
   },
   
   methods: {
     // 加载字典类型列表
     loadDictTypes() {
       getDictTypes().then(response => {
         this.dictTypeList = response.data;
       }).catch(error => {
         this.$message.error('加载字典类型失败: ' + error.message);
       });
     },
     
     // 字典类型变化时加载数据
     handleDictTypeChange(dictTypeId) {
       if (dictTypeId) {
         loadDictType(dictTypeId).then(response => {
           this.loadedDictType = response.data.dictType;
           this.loadedDictItems = response.data.dictItems;
           // 自动填充表单数据
           this.fillFormData();
         }).catch(error => {
           this.$message.error('加载字典类型数据失败: ' + error.message);
         });
       }
     },
     
     // 填充表单数据
     fillFormData() {
       if (this.form.changeType === 'MOD') {
         // 填充字典类型信息
         this.form.oldDctTp = this.loadedDictType.dctTp;
         this.form.newDctTp = this.loadedDictType.dctTp;
         this.form.oldDctTpNm = this.loadedDictType.dctTpNm;
         this.form.newDctTpNm = this.loadedDictType.dctTpNm;
         
         // 填充字典项
         this.form.itemChanges = this.loadedDictItems.map(item => ({
           changeOperation: 'MOD',
           oldDctSeq: item.dctSeq,
   ```

## 五、注意事项

1. **变更类型切换**：切换变更类型时，需重置表单数据，避免数据混乱
2. **字典类型选择**：修改/删除时，必须选择现有字典类型，防止无效操作
3. **原始值与新值**：修改操作时，必须同时记录原始值和新值，方便审批对比
4. **权限控制**：修改按钮仅对草稿状态的记录显示，避免无效操作
5. **数据验证**：前端和后端都需要进行数据验证，确保数据完整性和合法性
6. **响应式设计**：表单字段根据变更类型动态显示/隐藏，提高用户体验
7. **加载状态**：数据加载过程中显示加载提示，避免用户重复操作
