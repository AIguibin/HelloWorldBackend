# 权限系统模块整合文档

## 1. 概述

权限系统是平台的核心模块之一，负责管理用户、角色、权限和数据访问控制。本模块采用RBAC（基于角色的访问控制）模型，实现了精细化的权限管理，包括功能权限、数据权限、字段权限和时间权限等。

## 2. 数据库设计

### 2.1 核心表结构

基于RBAC权限体系的数据库设计包含14个核心表，用于管理用户、组织、角色和权限关系：

| 表名 | 描述 |
|------|------|
| `sys_user` | 用户信息表 |
| `sys_org` | 组织机构表 |
| `sys_dept` | 部门信息表 |
| `sys_role` | 角色信息表 |
| `sys_permission` | 权限信息表 |
| `sys_user_org` | 用户-组织机构关联表 |
| `sys_user_dept` | 用户-部门关联表 |
| `sys_user_role` | 用户-角色关联表 |
| `sys_role_perm` | 角色-权限关联表 |
| `sys_role_org` | 角色-组织机构关联表 |
| `sys_field_permission` | 字段权限表 |
| `sys_data_permission` | 数据权限表（原sys_data_rule） |
| `sys_time_permission` | 时间权限表 |
| `sys_biz_permission` | 业务规则权限表 |


## 3. 权限模型

### 3.1 权限分类

权限系统支持多种权限类型，包括：

1. **访问控制权限**：控制用户是否可以访问某个功能或资源
2. **数据范围权限**：控制用户可以访问的数据范围
3. **字段控制权限**：控制用户可以查看或修改的字段
4. **时间控制权限**：控制用户可以在什么时间访问系统
5. **业务规则权限**：基于业务规则的动态权限控制

### 3.2 数据权限模型

数据权限模型定义了用户对数据的访问范围，主要包括：

1. **全部数据**：用户可以访问系统中的所有数据
2. **本机构数据**：用户只能访问所属机构的数据
3. **本机构及子机构数据**：用户可以访问所属机构及其子机构的数据
4. **自定义数据范围**：用户只能访问指定范围内的数据

## 4. 实现方案

### 4.1 统一权限管理思路

统一权限管理的核心思想是将所有权限相关的功能封装到一个统一的权限服务中，提供一致的权限检查接口。主要包括：

1. **统一的权限服务接口**：定义了权限检查、权限分配、权限查询等核心方法
2. **模块化的实现**：将权限服务拆分为多个子模块，包括：
   - Token管理模块：负责令牌的生成、验证和刷新
   - 权限检查模块：负责检查用户是否具有某项权限
   - 数据范围计算模块：负责计算用户的数据访问范围
3. **灵活的配置**：支持通过配置文件或数据库动态调整权限规则

### 4.2 权限检查流程

权限检查的主要流程如下：

1. 用户请求资源
2. 系统验证用户身份
3. 获取用户的角色和权限信息
4. 根据权限类型执行相应的权限检查
5. 返回检查结果

## 5. 重构计划

### 5.1 AuthServiceImpl重构计划

AuthServiceImpl是权限系统的核心实现类，负责处理认证和授权相关的业务逻辑。重构计划将其拆分为多个模块化组件：

1. **TokenManager**：负责令牌的生成、验证和刷新
2. **PermissionChecker**：负责权限检查逻辑
3. **DataScopeCalculator**：负责数据范围计算
4. **OrgAccessValidator**：负责组织访问验证

重构后的AuthServiceImpl将更加模块化、可维护和可扩展。

### 5.2 SysUserOrgMapper重构计划

SysUserOrgMapper负责处理用户与组织机构的关联关系。重构计划主要包括：

1. 优化SQL查询，提高查询性能

3. 添加缓存机制，减少数据库查询次数
4. 完善错误处理，提高系统稳定性

## 8. 最佳实践

1. **权限设计原则**：
   - 最小权限原则：只授予用户完成工作所需的最小权限
   - 职责分离原则：不同职责的用户应具有不同的权限
   - 权限继承原则：子角色自动继承父角色的权限
   - 定期审查原则：定期审查和更新用户权限

2. **权限管理建议**：
   - 建立清晰的角色体系，避免角色过多或过少
   - 采用基于资源的权限设计，便于扩展和管理
   - 实现权限的分级管理，提高管理效率
   - 提供权限管理的可视化界面，方便管理员操作

3. **性能优化建议**：
   - 合理使用缓存，减少数据库查询次数
   - 优化权限检查逻辑，提高检查效率
   - 采用异步加载方式，提高系统响应速度
   - 定期清理无效的权限数据，减少数据量
