# 数据字典变更管理系统完整需求文档

## 一、项目概述

### 1.1 项目背景
系统中有业务数据字典表 `biz_ddct_item`、`biz_ddct_type`，需要日常团队不同的人进行变更，变更涉及增删改。为了规范变更流程，确保变更记录完整可追溯，需要建立标准化的数据字典变更管理系统。

### 1.2 项目目标
1. 实现数据字典类型维度的标准化变更流程
2. 提供可视化变更对比和审批功能
3. 确保变更记录完整可追溯
4. 支持团队协作和权限控制
5. 提高数据字典管理的效率和安全性

### 1.3 核心需求
- **变更记录管理**：开发填写变更表，提交后存储变更记录（不是流程记录）
- **可视化对比**：审批人员能看见原始的与要变更的，在同一个页面，方便审核
- **变更字段**：主要变更的字段为 `biz_ddct_item` 中的：
  - `DCT_SEQ`（排序号）
  - `DCT_GRP`（字典组）
  - `DCT_KEY`（字典键）
  - `DCT_VAL_NM`（字典值名称）
  - `DCT_TP_NM`（字典类型名称）
  - `DCT_VAL`（字典值）
  - `DCT_TP`（字典类型）
  - `DCT_DSC`（字典描述）

## 二、用户角色与权限

### 2.1 用户角色定义

| 角色 | 职责 | 权限 |
|------|------|------|
| 开发人员 | 提交字典变更申请 | 提交申请、查看历史、保存草稿 |
| 审批人员 | 审批变更申请 | 审批操作、查看所有记录、查看变更对比 |
| 系统管理员 | 执行变更、系统维护 | 所有权限（申请、审批、执行、查询） |
| 普通用户 | 使用字典数据 | 只读权限（查看变更记录） |

### 2.2 权限说明
- **开发人员**：可以创建变更申请、保存草稿、查看自己提交的变更记录
- **审批人员**：可以查看所有待审批记录、进行审批操作、查看所有变更记录
- **系统管理员**：拥有所有权限，包括执行变更操作
- **普通用户**：只能查看已执行的变更记录

## 三、功能需求

### 3.1 变更申请功能

#### 3.1.1 变更类型
支持三种变更类型：
- **新增（ADD）**：新增字典类型及其字典项
- **修改（MOD）**：修改现有字典类型及其字典项
- **删除（DEL）**：删除现有字典类型及其所有字典项

#### 3.1.2 新增字典类型流程
1. 选择变更类型为"新增"
2. 填写字典类型信息：
   - 字典类型编码（必填）
   - 字典类型名称（必填）
   - 字典类型描述（可选）
3. 添加字典项：
   - 可以添加多个字典项
   - 每个字典项需要填写：
     - 排序号（必填）
     - 字典键（必填）
     - 字典值名称（必填）
     - 字典值（必填）
     - 字典组（可选）
     - 字典描述（可选）
4. 填写变更原因（必填）
5. 填写变更影响（可选）
6. 保存草稿或提交申请

#### 3.1.3 修改字典类型流程
1. 选择变更类型为"修改"
2. **选择现有字典类型**：
   - 从下拉列表中选择要修改的字典类型
   - **系统自动加载该字典类型的所有信息**（包括字典类型信息和所有字典项）
   - 自动填充原始值到表单中
3. 修改字典类型信息：
   - 可以修改字典类型编码、名称、描述
   - 原始值自动显示，新值可以修改
4. 管理字典项：
   - **查看现有字典项列表**（显示原始值）
   - 可以新增字典项
   - 可以修改现有字典项（选择字典项后，自动加载原始值，可以修改新值）
   - 可以删除字典项（标记为删除）
5. 填写变更原因（必填）
6. 填写变更影响（可选）
7. 保存草稿或提交申请

#### 3.1.4 删除字典类型流程
1. 选择变更类型为"删除"
2. **选择现有字典类型**：
   - 从下拉列表中选择要删除的字典类型
   - **系统自动加载该字典类型的所有信息**（包括字典类型信息和所有字典项）
   - 显示要删除的内容，供用户确认
3. 填写变更原因（必填）
4. 填写变更影响（可选）
5. 保存草稿或提交申请

#### 3.1.5 草稿功能
- 支持保存草稿，草稿可以随时修改
- 草稿状态为"DRAFT"
- 草稿可以继续编辑或提交申请

### 3.2 审批功能

#### 3.2.1 待审批列表
- 显示所有待审批的变更申请
- 列表字段包括：
  - 变更单号
  - 变更类型
  - 原字典类型编码/名称
  - 新字典类型编码/名称
  - 申请人
  - 申请时间
  - 变更原因
  - 操作按钮（审批）

#### 3.2.2 审批详情页面
**核心需求：审批人员能看见原始的与要变更的，在同一个页面，方便审核**

**页面布局要求：**
1. **字典类型变更对比区域**：
   - 采用并排对比的方式展示
   - 左侧显示原始值，右侧显示新值
   - 变更的字段用颜色高亮标记（如：修改的字段用黄色背景，新增的字段用绿色背景，删除的字段用红色背景）
   - 对比字段包括：
     - 字典类型编码
     - 字典类型名称
     - 字典类型描述

2. **字典项变更对比区域**：
   - 采用表格形式展示，每行一个字典项
   - 表格列包括：
     - 操作类型（新增/修改/删除）
     - 原始值列组：
       - 排序号（原始）
       - 字典键（原始）
       - 字典值名称（原始）
       - 字典值（原始）
       - 字典组（原始）
       - 字典描述（原始）
     - 新值列组：
       - 排序号（新）
       - 字典键（新）
       - 字典值名称（新）
       - 字典值（新）
       - 字典组（新）
       - 字典描述（新）
   - 变更的字段用颜色高亮标记
   - 新增的字典项整行用绿色背景
   - 删除的字典项整行用红色背景
   - 修改的字典项，变更的字段用黄色背景

3. **变更统计信息**：
   - 显示变更摘要：
     - 字典类型：新增/修改/删除
     - 字典项：新增X项、修改Y项、删除Z项

4. **变更基本信息**：
   - 变更单号
   - 变更类型
   - 申请人
   - 申请时间
   - 变更原因
   - 变更影响

5. **审批操作区域**：
   - 审批结果选择（通过/拒绝）
   - 审批意见输入框（必填）
   - 提交审批按钮

#### 3.2.3 审批操作
- 审批人员可以查看变更详情
- 审批人员可以看到原始值与变更值的对比
- 审批人员可以填写审批意见
- 审批人员可以选择通过或拒绝
- 审批通过后，变更状态变为"APPROVED"，执行状态变为"PENDING"
- 审批拒绝后，变更状态变为"REJECTED"

### 3.3 变更执行功能

#### 3.3.1 待执行列表
- 显示所有已审批通过、待执行的变更申请
- 列表字段包括：
  - 变更单号
  - 变更类型
  - 原字典类型编码/名称
  - 新字典类型编码/名称
  - 申请人
  - 申请时间
  - 审批人
  - 审批时间
  - 操作按钮（执行）

#### 3.3.2 执行变更
- 系统管理员可以执行已审批通过的变更
- 执行变更时，需要真正对数据库表进行操作：
  - **字典类型变更**：
    - ADD：在 `biz_ddct_type` 表中插入新记录
    - MOD：更新 `biz_ddct_type` 表中的记录
    - DEL：删除 `biz_ddct_type` 表中的记录（逻辑删除或物理删除）
  - **字典项变更**：
    - ADD：在 `biz_ddct_item` 表中插入新记录
    - MOD：更新 `biz_ddct_item` 表中的记录
    - DEL：删除 `biz_ddct_item` 表中的记录（逻辑删除或物理删除）
- 执行过程需要事务性保证：
  - 所有操作在一个事务中执行
  - 如果任何一步失败，整个事务回滚
  - 执行状态更新为"FAILED"，并记录失败原因
- 执行成功后，执行状态更新为"SUCCESS"，并记录执行结果

#### 3.3.3 执行结果
- 执行成功：显示成功消息，更新执行状态
- 执行失败：显示失败原因，更新执行状态，记录错误信息

### 3.4 变更记录查询功能

#### 3.4.1 查询条件
支持以下查询条件：
- 变更单号
- 字典类型编码
- 变更类型（新增/修改/删除）
- 审批状态（草稿/待审批/已通过/已拒绝/已取消）
- 执行状态（待执行/执行中/成功/失败）
- 申请人
- 申请时间范围

#### 3.4.2 查询结果
- 列表展示查询结果
- 支持分页
- 列表字段包括：
  - 变更单号
  - 变更类型
  - 原字典类型编码/名称
  - 新字典类型编码/名称
  - 申请人
  - 申请时间
  - 审批状态
  - 执行状态
  - 变更原因

#### 3.4.3 详情查看
- 点击列表中的记录，可以查看变更详情
- 详情页面展示所有变更信息，包括：
  - 变更基本信息
  - 字典类型变更对比
  - 字典项变更对比
  - 审批信息
  - 执行信息

## 四、数据需求

### 4.1 数据实体

#### 4.1.1 字典类型（biz_ddct_type）
系统现有的字典类型表，存储字典类型的基本信息。

#### 4.1.2 字典项（biz_ddct_item）
系统现有的字典项表，存储字典项的详细信息。

#### 4.1.3 变更主记录（biz_ddct_type_change）
存储字典类型的变更记录，包括：
- 变更单号（唯一）
- 字典类型ID（关联到 biz_ddct_type）
- 变更类型（ADD/MOD/DEL）
- 原始字典类型信息（编码、名称、描述）
- 新字典类型信息（编码、名称、描述）
- 变更原因
- 变更影响
- 申请人信息
- 申请时间
- 审批状态（DRAFT/PENDING/APPROVED/REJECTED/CANCELED）
- 执行状态（PENDING/EXECUTING/SUCCESS/FAILED）
- 审批人信息
- 审批时间
- 审批意见
- 执行人信息
- 执行时间
- 执行结果
- 创建时间、更新时间、是否删除

#### 4.1.4 变更明细记录（biz_ddct_item_change）
存储字典项的变更记录，包括：
- 变更主记录ID（关联到 biz_ddct_type_change）
- 变更单号
- 字典项ID（关联到 biz_ddct_item）
- 操作类型（ADD/MOD/DEL）
- 原始字典项信息：
  - DCT_SEQ（排序号）
  - DCT_GRP（字典组）
  - DCT_KEY（字典键）
  - DCT_VAL_NM（字典值名称）
  - DCT_TP_NM（字典类型名称）
  - DCT_VAL（字典值）
  - DCT_TP（字典类型）
  - DCT_DSC（字典描述）
- 新字典项信息（同上）
- 执行状态（PENDING/SUCCESS/FAILED）
- 执行结果
- 字典项顺序
- 创建时间、更新时间、是否删除

### 4.2 数据关系
- 一个字典类型变更记录可以包含多个字典项变更记录（一对多）
- 字典类型变更记录关联到字典类型表（通过 dct_tp_id）
- 字典项变更记录关联到字典项表（通过 dict_id）

## 五、API需求

### 5.1 变更申请相关API

#### 5.1.1 获取字典类型列表
```
GET /api/dict/change/dict-types
功能：获取所有启用的字典类型列表，用于下拉选择
返回：字典类型列表（包含ID、编码、名称）
```

#### 5.1.2 加载字典类型和字典项数据
```
GET /api/dict/change/load-dict-type/{dictTypeId}
功能：根据字典类型ID加载字典类型信息和所有字典项
返回：字典类型信息和字典项列表
```

#### 5.1.3 提交变更申请
```
POST /api/dict/change/apply
功能：提交变更申请
参数：DictChangeApplyDTO
返回：变更记录信息
```

#### 5.1.4 保存草稿
```
POST /api/dict/change/draft
功能：保存变更申请草稿
参数：DictChangeApplyDTO
返回：变更记录信息
```

### 5.2 审批相关API

#### 5.2.1 获取待审批列表
```
GET /api/dict/change/pending/approve
功能：获取所有待审批的变更申请列表
返回：变更申请列表
```

#### 5.2.2 获取变更详情
```
GET /api/dict/change/detail/{changeId}
功能：获取变更申请的详细信息，包括字典类型变更和字典项变更
返回：变更详情（包含原始值和新值的对比数据）
```

#### 5.2.3 审批变更
```
POST /api/dict/change/approve/{changeId}
功能：审批变更申请（通过或拒绝）
参数：ApproveDTO（包含审批结果和审批意见）
返回：操作结果
```

### 5.3 执行相关API

#### 5.3.1 获取待执行列表
```
GET /api/dict/change/pending/execute
功能：获取所有已审批通过、待执行的变更申请列表
返回：变更申请列表
```

#### 5.3.2 执行变更
```
POST /api/dict/change/execute/{changeId}
功能：执行变更申请，真正对数据库表进行操作
返回：执行结果（成功或失败，包含失败原因）
```

### 5.4 查询相关API

#### 5.4.1 查询变更记录
```
GET /api/dict/change/list
功能：根据查询条件查询变更记录，支持分页
参数：ChangeQueryDTO（包含各种查询条件）
返回：分页结果
```

## 七、非功能需求

### 7.1 性能需求
- 列表查询响应时间 < 2秒
- 详情查询响应时间 < 1秒
- 支持分页，每页默认10条，最大100条

### 7.2 安全需求
- 需要用户登录才能访问
- 不同角色有不同的权限
- 操作需要记录操作日志

### 7.3 可用性需求
- 系统可用性 > 99%
- 支持并发操作
- 事务性保证，确保数据一致性

## 九、附录

### 9.1 术语表
- **变更记录**：记录字典变更的详细信息，包括原始值和新值
- **变更对比**：在同一页面展示原始值与变更值的对比
- **草稿**：未提交的变更申请，可以随时修改
- **审批**：对变更申请进行审核，决定是否通过
- **执行**：将已审批通过的变更真正应用到系统中
