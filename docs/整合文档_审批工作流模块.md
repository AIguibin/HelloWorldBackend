# 审批工作流模块整合文档

## 1. 概述

审批工作流系统是平台的核心业务模块之一，用于管理和处理各类审批请求，包括变更记录审批、发版审批等。该系统支持灵活的审批流程定义、多角色参与、动态表单和完整的审批历史记录。

## 2. 系统架构

### 2.1 架构设计

审批工作流系统采用分层架构设计，包括前端展示层、业务逻辑层、流程引擎层和数据持久层：

1. **前端展示层**：负责审批请求的创建、展示和处理，包括：
   - ChangeRecordList.vue：变更记录列表，用于提交变更申请
   - ApprovalTodoList.vue：审批待办列表，用于处理审批请求
   - ApprovalForm.vue：通用审批申请表单

2. **业务逻辑层**：负责处理审批业务逻辑，包括：
   - 审批请求的创建和更新
   - 审批流程的触发和执行
   - 审批结果的处理和通知

3. **流程引擎层**：负责审批流程的定义和执行，包括：
   - 流程节点的定义和配置
   - 流程状态的转换和管理
   - 审批规则的执行和验证

4. **数据持久层**：负责审批数据的存储和管理，包括：
   - 审批请求数据
   - 审批流程数据
   - 审批历史记录

### 2.2 审批流程节点

审批流程包括四个关键节点，形成完整的审批链路：

| 节点 | 职责 | 对应前端组件 |
|------|------|--------------|
| 开发人员提交变更申请 | 开发人员创建并提交变更请求 | ChangeRecordList.vue |
| 项目小组长审核 | 项目小组长审核变更请求 | ApprovalTodoList.vue |
| 项目大组长审核 | 项目大组长审核变更请求 | ApprovalTodoList.vue |
| 技术架构师评审 | 技术架构师评审变更请求 | ApprovalTodoList.vue |

## 3. 开发计划

### 3.1 后端API开发

1. **审批请求管理API**：
   - 创建审批请求：`POST /api/approval-requests`
   - 查询审批请求列表：`GET /api/approval-requests`
   - 查询审批请求详情：`GET /api/approval-requests/{id}`
   - 更新审批请求：`PUT /api/approval-requests/{id}`
   - 删除审批请求：`DELETE /api/approval-requests/{id}`

2. **审批流程管理API**：
   - 触发审批流程：`POST /api/approval-requests/{id}/start`
   - 处理审批任务：`POST /api/approval-tasks/{id}/handle`
   - 查询审批历史：`GET /api/approval-requests/{id}/history`

3. **动态表单API**：
   - 查询表单字段：`GET /api/approval-forms/{businessType}/fields`
   - 验证表单数据：`POST /api/approval-forms/{businessType}/validate`

### 3.2 前端组件开发

1. **ApprovalForm.vue**：
   - 通用审批申请表单组件
   - 支持多种业务类型的动态表单字段
   - 包含业务类型选择、基本信息填写、动态表单字段、附件上传等功能
   - 支持提交审批和保存草稿操作

2. **ApprovalTodoList.vue**：
   - 审批待办列表组件
   - 展示待处理的审批任务
   - 支持审批通过、拒绝和转办操作
   - 显示审批任务的详细信息和历史记录

3. **ChangeRecordList.vue**：
   - 变更记录管理组件
   - 用于创建和管理变更记录
   - 提供提交审批的入口

### 3.3 数据库设计

1. **审批请求表**：`approval_request`
   - 存储审批请求的基本信息
   - 字段包括：id, business_type, title, description, status, created_by, created_time, updated_time

2. **审批流程表**：`approval_process`
   - 存储审批流程的定义和状态
   - 字段包括：id, request_id, current_node, status, created_time, updated_time

3. **审批任务表**：`approval_task`
   - 存储审批任务的信息
   - 字段包括：id, process_id, node_name, assignee, status, created_time, updated_time

4. **审批历史表**：`approval_history`
   - 存储审批历史记录
   - 字段包括：id, request_id, node_name, operator, action, comment, created_time

### 3.4 测试数据生成

1. 生成审批请求测试数据

## 4. 核心功能实现

### 4.1 审批流程状态转换算法

审批流程状态转换算法负责管理审批流程的状态变化，确保流程按照预期执行。核心状态包括：

1. **初始化**：审批请求创建成功，等待触发
2. **审批中**：审批流程已触发，正在执行
3. **已通过**：所有审批节点通过
4. **已拒绝**：任意审批节点拒绝
5. **已撤回**：申请人撤回审批请求

状态转换规则：
- 初始化 → 审批中：触发审批流程
- 审批中 → 已通过：所有审批节点通过
- 审批中 → 已拒绝：任意审批节点拒绝
- 审批中 → 已撤回：申请人撤回

### 4.2 动态API替换

approval.js动态API替换优化方案旨在解决硬编码API地址的问题，实现API地址的动态配置：

1. **配置文件管理**：将API地址配置到独立的配置文件中
2. **动态加载机制**：在应用启动时动态加载API配置
3. **API请求封装**：封装API请求函数，自动使用配置的API地址
4. **环境切换支持**：支持不同环境（开发、测试、生产）的API地址切换

### 4.3 前后端逻辑关联

审批功能前后逻辑关联分析及调整方案旨在确保前后端逻辑的一致性和完整性：

1. **前端触发逻辑**：
   - ChangeRecordList.vue：提交变更记录到审批流程
   - ApprovalForm.vue：直接创建审批请求

2. **后端处理逻辑**：
   - 统一审批流程创建逻辑
   - 确保审批状态与业务对象状态同步
   - 实现审批结果的通知机制

3. **数据交互方式**：
   - ChangeRecordList.vue：调用`submitApproval(row.id)`方法，将变更记录ID提交到后端
   - ApprovalForm.vue：调用`/api/approval-requests` API，提交完整的审批表单数据

## 7. 问题修复

### 7.1 修复ApprovalForm.vue业务类型下拉框没有选项值的问题

**问题描述**：ApprovalForm.vue的业务类型下拉框没有显示选项值

**解决方案**：
1. 检查API调用，确保正确获取业务类型列表
2. 检查数据绑定，确保选项值正确绑定到下拉框
3. 添加错误处理，显示API调用失败的提示信息
4. 添加加载状态，提高用户体验

### 7.2 统一审批触发机制

**问题描述**：系统存在两个不同的审批触发点，导致审批流程的一致性问题

**解决方案**：
1. 抽象出通用的审批触发服务，统一处理审批流程的创建
2. 明确组件职责边界，ChangeRecordList.vue专注于变更记录管理，ApprovalForm.vue专注于审批申请创建
3. 实现审批流程的统一状态管理，确保状态更新的一致性

### 7.3 审批流程状态同步

**问题描述**：审批流程状态与业务对象状态不同步

**解决方案**：
1. 在审批流程状态变更时，自动更新相关业务对象的状态
2. 实现状态变更的事件通知机制，确保所有相关系统都能及时获取状态变更信息
3. 添加状态一致性检查，定期验证审批流程状态与业务对象状态是否一致
